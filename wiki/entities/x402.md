# x402

A payment rail built on the HTTP **402 "Payment Required"** status code, stewarded by the
independent **x402 Foundation** (`x402-foundation/x402`, Apache-2.0) and supported by [[cloudflare]],
Coinbase, and infrastructure partners (source-cloudflare-economy, source-agent-protocol-landscape-2026).

## Flow

1. Agent requests a resource
2. Server quotes a price (often a fraction of a cent)
3. Agent pays (it holds a wallet / agent-addressable identity)
4. Agent retries with proof of payment
5. Verification at the edge or gateway before the request reaches origin

No checkout flow, no account creation, no sales call — **the request itself is the
transaction.**

## Ecosystem Complements (2026)

In the broader agentic commerce landscape:
- **[[ap2|AP2 (Agent Payments Protocol)]]:** Provides cryptographic user intent and authorization
  mandates prior to initiating payment.
- **MPP (Machine Payments Protocol):** Stripe/Tempo IETF draft for streaming micropayments and
  session-based HTTP 402 authorizations.
- **x402:** Focuses on the settlement layer (onchain stablecoins and fiat).

## Kubona integration (planned)

- **Optional rail, additive, not a replacement** — sits *underneath* the two-stage human
  approval gate on the [[cost-governance]] server; sub-cent-to-sub-dollar transactions
  (simulator-tier runs, algorithm-library lookups) skip human approval (source-gap-analysis-plan).
- Standard rail beats bespoke: any agent that understands x402 can transact with Kubona
  with zero custom integration work.
- Design the cost-gov payment interface x402-compatible from Phase 1; activate Phase 5+
  (dormant by design until business activation — see [[questions]] Q-23).
- The audit ledger doubles as the payment-proof ledger with no structural rework.
